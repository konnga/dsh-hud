# dsh-hud

DeepSeek HUD 状态面板：分支、ahead/behind、改动清单与差异，外加「这个会话改过哪些文件、审到哪了、跑了什么工具」。

![输入框上方的胶囊行：左边是 Git 状态，中间是工具与技能，右边是本次会话运行时长（图中的余额胶囊是后加的，截图尚未更新）](docs/images/capsules.webp)

## 安装

桌面端「设置 → 插件 → 添加插件」里填 `@konnga/dsh-hud`。

本地开发时把 profile 的依赖指向仓库（改动即时可见；客户端代码要重启应用才重读）：

```json
"@konnga/dsh-hud": "link:/path/to/dsh-hud"
```

## 你会看到什么

### 胶囊（输入框上方那一行）

```
dsh-hud · git:(main*) ↑1 ↓2 M4 A1 ?1 │ ●3   │   ✓ bash ×16 │ …   │   ⏱ 2h 14m   │  ¥128.40+
```

> 几枚胶囊的**悬停提示是插件自己画的气泡**（不用浏览器原生 tooltip —— 它在真机上不出现，延迟与样式也控制不了）。

**Git**（最左）

- `dsh-hud` —— 工作区名（太长从中间省略，完整路径看悬停）。不在 git 仓库里也会显示。
- `git:(main*)` —— 分支。`*` 表示工作区不干净；detached 时是 `git:(detached abc1234)`。
- `↑1 ↓2` —— 与上游的领先 / 落后（为 0 不显示）。
- `M4 A1 ?1` —— 改动计数，只列非零项：`M` 改 · `A` 增 · `D` 删 · `R` 重命名 · `C` 复制 · `T` 类型 · `?` 未跟踪 · `!` 冲突。
- `●3` —— 本会话改过 3 个文件（没有就不显示）。

**工具**（中间，运行过的工具才出现）

```
◐ bash: pnpm test 1.2s                                     ← 正在跑，秒数实时跳
✓ bash ×16 │ ✓ apply_patch ×6 │ skills: office-xlsx ×2 +2   ← 空闲
```

- 每个工具一个计数，前面的 `✓` / `✗` 是**它自己最近一次**调用的结果。
- `skills:` 后面是技能名（看得出是哪一个，不是"技能调了几次"）。
- 最多铺 3 个工具 + 2 个技能，其余收成 `+k`；悬停里有完整清单与最近几条结果。

**会话计时**（最右，余额胶囊之后）

```
⏱ 2h 14m
```

- **本次会话已运行多久**。口径与 [codex-hud](https://github.com/konnga/codex-hud) 的会话时长一致：`现在 − 会话创建时刻`（含等待与空闲）。格式 `<1m` / `45m` / `2h 14m` / `3d 2h`。
- 悬停补上这段时间真正在干什么：

  ```
  本次会话运行时长 · 创建于 2026-10-14 17:58 · 其中模型 1h 29m、工具 23m · 27 轮 / 380 步
  ```

  后两项来自内置 `sessionStats` 投影；那个投影没有时只显示挂钟时长，不编造。
- 刚重启的头几秒可能还没有它：会话是异步恢复进宿主存储的（实测约 30 秒）。所以取数失败按 **3 秒**重问，拿到后改成 60 秒一次。会话已归档或宿主没有 `sessions` 服务时，整枚不画。

*同一套气泡也用在 Git 与工具胶囊上（Git 那颗是多行的：完整路径 / 上游 / 各类型计数）。*

**余额**（计时之前）—— 它画的是**当前会话真正在用的那个账本**：

| 会话用的是                                         | 胶囊显示                         | 例               |
| -------------------------------------------------- | -------------------------------- | ---------------- |
| DeepSeek 平台账号（`deepseek-account`）          | 平台账号钱包余额                 | `¥128.40+`    |
| 官方 API Key（`deepseek-official`）              | `GET /user/balance` 的钱包     | `¥128.60+`    |
| 第三方中转站，API Key 就能读到剩余                 | 那家自己报的剩余额度             | `$2,265.33`    |
| 第三方中转站，剩余额只给网页登录态（配了网页令牌） | 账号余额（站点后台那个数）       | `$137.48`      |
| 中转站把额度写成"无限"占位 / 没配网页令牌          | **已用**（剩余未知，不编） | `已用 $1.24`   |
| 认不出的站（两套协议都不通）                       | 站名 + `--`（读不到就直说）   | `api404 --`   |
| 还没查出来（新会话 / 刚换会话 / 宿主还没就绪）        | `--`（**不拿官方账号余额顶上**） | `--`          |

配好后台凭据之后，中转站那一枚的悬停长这样 —— 四个读数按语义上色（下面说为什么）：

**DeepSeek 平台账号**的悬停（中转站那一路换成上面那五行，没有赠送余额那两行）：

```
DeepSeek 账号余额
¥8.60
赠送余额 ¥2.00
较上次刷新 -¥0.30（2026-10-27 08:45）
更新于 2026-10-27 08:50
```

气泡里只有**读数**，没有操作说明、也没有提醒话术：那几句"点一下刷新 / 右键开用量页 / 余额低于 …… 记得充值"
都已删掉（它们会把整块明细撑成七行、还挤掉真正会变的那几个数）。两个动作仍然在：**左键点击 = 立即刷新**，
**右键 = 在新标签打开平台用量页**。低余额也只由胶囊上的 `⚠` + 警示色表达，不在气泡里复述。

- 余额来自 DSH 自己的账号接口（`remote.account.getBalance`，与「设置 → 账号」是同一份数），**只读**、不落盘。
- 显示规则与 DSH 账号卡片逐条一致：`¥0.00` / `<¥0.01`（不足一分）/ `¥1,234.56`（千分位、向零截断两位）/ 负数带 `-`。币种符号由金额本身带（`¥` / `$`），不会再额外多画一个。
- 末尾 `+` —— 还有赠送余额；具体多少在悬停里。末尾 `?` 颜色发黄 —— 最近一次刷新失败，屏幕上是上一次的数（悬停里会说是什么时候的）。
- **低余额提醒** —— 低于阈值（默认 ¥10）时胶囊前面加 `⚠`、金额变成警示色（**只在胶囊上，不写文案**）。
  阈值可用 localStorage 键 `dsh-hud.balanceLow` 覆盖（写十进制数，例如 `localStorage.setItem('dsh-hud.balanceLow', '50')`），刷新页面生效。
- **变化量** —— 悬停里给「较上次刷新 -¥0.30（22:37）」。这是**我们自己两次采样之间**的差，不是平台的"今日消耗"；
  跨重启不累计（中间发生过什么我们并不知道），所以措辞写的是"较上次刷新"。
  减法按十进制对齐做整数运算，`8.6 - 8.3` 就是 `0.30`，不会出现 `0.2999999999999998`。
- 平时 5 分钟刷一次（它背后是平台的一次真实网络请求，余额也按分钟变）；**左键点击**可立即刷新。
- **读不到就不画**：没登录、没有账号插件、一个钱包都没有时这枚胶囊不出现，也不会画 `¥0.00` 冒充"没钱"。

### 中转站的「账号余额」：为什么有的站只给得出用量

new-api 家族（`ur` / `muyuan` / `happycoding` / `ccwu` 都是）把数据分在两套鉴权后面：

| 接口                                    | 认什么                                                              | 给什么                                                        | 实测（`ur`）                                    |
| --------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------- |
| `GET /dashboard/billing/subscription` | ✅ API Key                                                          | 额度上限                                                      | `hard_limit_usd: 100000000`（**占位值**） |
| `GET /dashboard/billing/usage`        | ✅ API Key                                                          | **这枚 Key** 的累计用量                                 | `$479.44`                                       |
| `GET /api/user/self`                  | ❌ **只认后台凭据**（PAT / 登录会话；挂在 `UserAuth()` 下） | **账号**余额 + 账号累计用量 + 请求数                    | `$855.69` / `$526.66` / `3685`              |
| `GET /api/usage/token/`               | ✅ API Key                                                          | 这枚 Key 的额度口径（若为"无限"则 `unlimited_quota: true`） | `total_available: -199583909`                   |

所以**账号余额**（后台「当前余额」那个数）只有一条路能读，而那条路不认 `sk` 开头的 Key。
要看到它，给某个站配一枚**后台凭据** —— **点一下余额胶囊就会弹出设置面板**，粘进去即可：

```
┌─ 天机访问令牌 ────────────── ur ─┐
│ 这个站的「当前余额」只对后台登录态可见    │
│ （API Key 读不到）。去站点「个人设置 →    │
│ 访问令牌」新建一枚，权限勾 profile:read， │
│ 粘进来就行。                              │
│ [••••••••••••••••••••]                  │
│ 将写入 UR_ACCESS_TOKEN                   │
│                        [保存] [取消]     │
└──────────────────────────────────────────┘
```

- 令牌去哪拿：站点「个人设置 → 访问令牌」新建一枚，scope 勾 **`profile:read`**（长期有效）。
  老版本站点没有访问令牌页面时，也可以从浏览器 localStorage 的 `user.token` 复制一枚登录令牌（会过期）。
- **不用碰 `~/.dsh/.credentials.yaml`**：引用名（`UR_ACCESS_TOKEN`）由插件从 `UR_API_KEY` 推导，
  写入走 DSH 的凭据服务。让用户手改那个文件等于把"配一个令牌"变成"改一个配置文件"——
  手滑一个缩进整份凭据就读不出来。
- 令牌**不回显**：输入框是 `password`，不进 localStorage、不进日志、不进快照，
  宿主也从不把它回传给浏览器（答复里只有引用名）。
- 存好立刻重取一次（跳过宿主 60 秒缓存），面板自动收起 —— 粘完就能看见数字变出来。
- 令牌过期（换设备 / 退出登录 / 站点重置）时**自动退回用量那一路**，不会整枚消失。
  没配凭据的站照旧只报用量；`ur —` 也是"没配凭据"的样子，点它同样弹面板。
- **兑换率不写死**：`quota` 是整数，除以站点公开在 `/api/status` 的 `quota_per_unit`（实测 `ur` = `500000`）才是金额；
  站点用非美元显示时按它自己公布的 `usd_exchange_rate` 换算。拿不到口径时才退回 new-api 的默认值，并在日志里留痕。
  （这四个站实测 `quota_display_type` 全是 `USD`，非美元那条换算分支对它们用不到，属防御性代码。）
- **逐位对过账**（两次独立核对，间隔数小时，四个数各自按自己的口径对得上）：
  - `ur`：`427845000 / 500000 = $855.69`、`263330000 / 500000 = $526.66`、`request_count = 3685`；
  - `happycoding`（就是上面那张效果图那台）：`68725535 / 500000 = $137.45`、`3774465 / 500000 = $7.55`、
    `request_count = 3525`、`total_usage = 127.0872 分 = $1.27` —— 截图时是 `$137.48 / $7.51 / 3,514 / $1.24`，
    相差的就是这十几分钟里真实用掉的量（余额降、其余三个升），**不是换算误差**。

### 什么时候显示 `--`

胶囊只画**读到的读数**。还没读到、或读不到的时候画 `--`，**绝不拿平台账号的余额顶上** ——
那个数未必是这次会话要花的钱，填进来等于报一个与本次会话无关的数。

| 状态 | 胶囊 |
| --- | --- |
| 读到余额 | `$742.23` |
| 只知道站、读不到（如 `api404`） | `api404 --` |
| 连站都还不知道（新会话、刚换会话、宿主还没就绪） | `--` |
| 宿主明确说"这个提供方的账本就是平台账号" | 平台账号余额 `⚠ ¥8.60` |

换会话是**同步清空**的：绑定新会话那一瞬旧账本就没了（`unknown` → `--`），紧接着按新会话的
模型来源查一次。所以切换时不会出现"屏幕上还写着上一个会话的站名和金额"——那是另一个账本的钱。

### 悬停里那两个「已用」是两本账

配好后台凭据之后，悬停里同时列出**账号**与**本 Key** 两个已用 —— 它们是两个不同的数（上面那张效果图就是这一屏）：

```
happycoding
余额 $137.48          ← /api/user/self 的 quota ÷ quota_per_unit
API 请求 3,514        ← 同一个响应的 request_count（紧跟余额：它是唯一一个次数，不是钱）
账号已用 $7.51        ← 同一个响应的 used_quota（整个账号）
本 Key 已用 $1.24     ← /dashboard/billing/usage 的 total_usage（只有这枚 Key）
更新于 2026-10-27 16:45
```

同一个站上这两个数能差出一截（这台上：账号 `$7.51` vs 本 Key `$1.24`，差的那部分是账号下另一个 Key 的用量；
`ur` 上则是 `$526.66` vs `$479.44`），所以它们是**两个字段、两行**，不是靠一个标记二选一 ——
塞进一个字段就必须丢掉一个真实读数。

**数字为什么分三种颜色**：这一屏里三个是钱、一个是次数，所以按语义分开 ——

| 颜色 | 谁用它 | 为什么 |
| --- | --- | --- |
| 绿 | 余额 | "还剩多少"的通行读法 |
| 蓝 | API 请求 | 它是**次数**不是金额；同一个颜色会被读成第三个金额 |
| 琥珀 | 两个「已用」 | 分类色（"这是消耗"），**不是在报警** |
| 灰 | 标签 / 站名 / 更新时间 | 时间戳和标签不是读数，染上就等于满屏是色、没有重点 |

颜色全部取自 DSH 自己的主题令牌（`state-success-primary` / `state-business-primary` / `state-warn-primary`），
深浅色主题各有一套取值，不写死十六进制。

行序是 `余额 → API 请求 → 账号已用 → 本 Key 已用`：请求数紧跟余额，因为它是这一屏里唯一一个**次数**而不是金额，
夹在两个金额中间容易被读成第三个金额。

### 「已用」不是「本月」

这些站**都忽略 `start_date` / `end_date`**（实测四个站、四个区间回的完全一样），
所以那个数不是「本月」而是**累计**。既然区间不生效，请求就发全历史区间、标签写「累计」——
不写一个按月的标签去暗示它按月算。
